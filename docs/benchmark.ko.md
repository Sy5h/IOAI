# 공식 공개 데이터 실측 — 1차 기록

이 문서는 첫 실험의 결과를 보존한 기록이다. 이후 단순한 방법으로 더 개선한 현재 코드의 비교는 [2차 개선 결과](improvements-round2.ko.md)를 확인한다. 아래의 ‘최종’은 1차 실험 종료 시점(commit `991a49b`)을 뜻한다.

측정일: 2026-10-16. 공개된 IOAI 공식 데이터와 채점식으로 이 저장소의 코드를 실행했다. 비교 기준은 기존 저장소 commit [`b3e60ae`](https://github.com/Sy5h/IOAI/tree/b3e60ae8e14b55d97c44214dc1ec7d8e49295a89)이다. 출제자의 baseline과 이 저장소의 이전 코드는 별도로 구분한다.

공개된 `private/` 경로의 A/B 자료도 평가에 사용했다. 현재 공개 파일의 재평가 결과이며 실제 대회 서버 제출이나 새로운 비공개 데이터에 대한 결과는 아니다. 모든 점수는 읽기 쉽도록 100점 척도로 표시한다. 문제마다 채점식이 달라 서로 직접 비교하면 안 된다.

## 최종 기본값 요약

각 칸은 **100점 척도 점수 / 실행 시간(초)**이다. 문제마다 채점식이 다르다. Field는 별도 Linux CPU runner에서, 나머지는 아래 로컬 PC 환경에서 측정했다.

| 문제 | A | B |
|---|---:|---:|
| Find the Order | 76.52 / 362.131 | 74.09 / 266.970 |
| Robot Chasing | 64.92 / 98.00 | 63.94 / 97.53 |
| Potato | 44.25 / 6.406 | 48.90 / 8.047 |
| Double Agent Dilemma | 97.54 / 154.954 | 97.38 / 164.672 |
| Ghost of the Machine | 90.52 / 90.360 | 90.81 / 85.469 |
| IOAI Field | 85.50 / 20.764 | 72.74 / 24.920 |

Dilemma는 A/B 모두 개선됐다. Field는 A 하락과 B 상승이 함께 있는 변경이다. Order·Robot·Potato·Ghost는 비교 후 기존 기본값을 유지했다. 아래 표들은 배포 기본값과 채택하지 않은 후보를 구분한다.

## Find the Order

Whisper 전사와 Qwen 연결 점수로 순서를 찾는 기존 코드를 유지했다. 모델 없이 첫 두 발화만 고정하는 prefix-only와 MFCC 화자 교대 후보도 비교했다. 개발용 pretrain 20개에서 prefix-only 69.3335점, 화자 교대 후보 70.5481점, 기존 Whisper+Qwen 75.5781점이었다.

공개 pretest 20개에서 기존 코드는 **75.9140점 / 82.715초**로 모든 대화를 처리했다. Prefix-only는 68.9534점 / 0.263초였다. 실제 오디오 길이보다 큰 RIFF 크기를 선언한 공식 WAV 한 개는 고정 URL에서 다시 내려받아 SHA-256 일치를 확인했고, 파일을 수정하지 않고 읽을 수 있는 오디오로 처리했다. 해당 경고로 fallback이 발생하지는 않았다.

| 설정 | A 100대화 | B 100대화 |
|---|---:|---:|
| Prefix-only | 68.9690 / 0.551초 | 69.1460 / 0.476초 |
| Prefix + MFCC 화자 교대 후보 | 69.0880 / 42.270초 | 69.7803 / 43.236초 |
| **기존 Whisper + Qwen, 최종 기본값** | **76.5214 / 362.131초** | **74.0884 / 266.970초** |

모델을 사용한 A/B는 각각 **100/100개 대화를 Qwen까지 처리**했다. Prefix fallback과 유효하지 않은 순열은 모두 0개였다. 두 실행 모두 원본과 동일한 코드·540초 예산·ASR 시간 비율 .55·배치 8/4를 사용했다. CPU 음향 후보는 GPU 없이 약 69점을 얻는 간단한 선택지이며, 기본 파이프라인보다 점수가 높지는 않았다.

## Robot Chasing

학습 60,000행 중 48,000행/12,000행을 로봇별로 고정 분할했다. 내부 검증에서 MLP 64.7333점, ExtraTrees 65.1500점, 작은 HistGradientBoosting 모델 66.5083점이었다. 선택한 트리 모델은 A에서 하락하고 B에서 소폭 상승해 기본값을 교체할 근거가 충분하지 않았다. **MLP를 유지하고 `--model hist`를 선택 옵션으로 남겼다.**

| 설정 | 공개 pretest 600행 | A 3,600행 | B 3,600행 |
|---|---:|---:|---:|
| 기존 MLP, 최종 기본값 | 63.00 / 100.92초 | 64.92 / 98.00초 | 63.94 / 97.53초 |
| 내부 검증에서 선택한 트리 후보 | — | 63.75 / 100.77초 | 64.53 / 96.10초 |

최종 기본값 유지는 A/B의 혼재한 결과를 본 뒤 내린 보수적인 결정이다. 이 선택 자체를 새로운 미지의 데이터에서 검증한 것으로 표현하지 않는다. 예외 발생 시 이미 저장한 예측을 보존하는 수정도 추가했으며, 정상 종료한 위 실측에는 그 예외 경로가 사용되지 않았다.

## Potato

120게임을 한 프로세스에서 순서대로 실행했다. A/B는 공개된 실제 심판용 임베딩으로 채점했다. 기존 설정을 유지한다.

| 설정 | 공개 임베딩 public 120게임 | A 120게임 | B 120게임 |
|---|---:|---:|---:|
| 기존 temperature .06, 최종 기본값 | 84.90 / 6.281초 | 44.25 / 6.406초 | 48.90 / 8.047초 |
| 개발 데이터에서 선택한 .008 후보 | 97.80 / 4.047초 | 44.17 / 9.391초 | 49.17 / 8.438초 |
| 참고: 공식 nearest baseline | 36.00 / 1.281초 | 15.00 / 1.578초 | 17.08 / 1.469초 |

공개 target을 제외한 160단어 개발 실험에서 temperature를 고르면 공개 임베딩 점수는 크게 올랐다. 그러나 A/B에서는 개선이 거의 유지되지 않았다. 따라서 **97.80점을 실제 심판 임베딩에서의 성능으로 소개하지 않는다.** `--temperature .008`은 공개 임베딩 실험용 옵션으로만 안내한다.

기본값 복원 후 A를 추가 실행한 `portable-default-a`는 같은 **44.25점 / 6.093초**였다. 표에는 최초 측정 시간을 유지했으며 가장 빠른 반복만 골라 쓰지 않았다.

## Double Agent Dilemma

공식 ResNet·ViT 모델에서 두 방향 공격을 각각 수행한다. 학습 이미지 20장의 비교에서 선택한 작은 학습률 .0001은 변경량을 줄였지만, 단독 적용한 공개 test에서 200개 중 4개 공격이 실패해 점수가 오히려 떨어졌다. 실패할 때 기존 학습률 .001로 재시도하고, 재시도에 이미지별 시간의 35%를 남기는 간단한 보완을 채택했다.

| 설정 | A 100장·200공격 | B 100장·200공격 |
|---|---:|---:|
| 기존 학습률 .001 | 97.18955 / 70.796초 | 97.04805 / 69.235초 |
| 작은 학습률 + 재시도, 시간 예약 없음 | 97.53715 / 148.219초 | 96.94223 / 237.125초 |
| **최종: 작은 학습률 + 재시도 시간 35% 예약** | **97.53718 / 154.954초** | **97.38016 / 164.672초** |

최종 A/B는 공격 **400/400개 성공**, 점수는 각각 **+0.34762 / +0.33212점**이다. 실행 시간은 기존보다 약 2.2배 / 2.4배 늘었지만 이번 장비에서는 설정한 660초 안에 완료됐다. 기존 학습률 정책을 재현하려면 `--learning-rate .001`, 재시도 예약이 없는 실험은 `--first-attempt-fraction 1`로 선택한다.

공개 test의 기존 코드는 97.11915점 / 77.235초였고, 작은 학습률 단독 후보는 95.72252점 / 159.547초였다. **공개 test는 최종 예약 코드로 재실행하지 않았다.** 최종 A/B는 초기 A/B 결과에서 시간 예약 문제를 발견한 후 수행한 개발 재평가다. 새로운 비공개 데이터에서의 독립 확증은 아니다. 실패한 초기 후보와 시간 예약 없는 중간 결과도 JSON에 보존했다.

## Ghost of the Machine

학습 글 1,221개를 사용했다. 별도 pretrain 200개는 모두 학습 글과 중복되어 합치지 않았다. 학습 글의 고정 holdout 183개에서 24개 간단한 회귀·경계 선택 설정을 비교했지만 실제 평가에서 개선을 확인하지 못했다. **C2 / prior .25를 유지한다.**

| 설정 | 공개 pretest 60글 | A 380글 | B 380글 |
|---|---:|---:|---:|
| 기존 C2 / prior .25, 최종 기본값 | 94.36 / 71.266초 | 90.52 / 90.360초 | 90.81 / 85.469초 |
| holdout에서 고른 C10 / prior 0 후보 | 93.11 / 77.094초 | 90.44 / 91.969초 | 실패 / 36.656초, 점수 없음 |

원본 B를 한 번 더 실행해 **90.809690점 / 83.375초**를 얻었다. 점수와 정확한 경계 334/380개가 첫 실행과 일치했다. 길이순 배치 시도와 원래 배치로 복원한 후보 실행에서 각각 Windows native 종료 `0xC0000409`가 발생했다. 원인은 미확인이다. 실패한 실행을 0점이나 성공 결과로 바꾸지 않고 실패로 기록했다. 길이순 배치 최적화와 C10 후보는 채택하지 않았다.

## IOAI Field

공식 Linux 보호 런타임에서 설정마다 처음부터 학습했다. A와 B는 각각 공개된 설정 한 개이며, 최종 채점은 공식 설정의 영역당 512개 표본·entropy 10회 반복을 그대로 사용했다.

먼저 학습 횟수 2,500/10,000/25,000을 공개 설정의 두 seed로 비교했다. 평균 점수는 85.6160/79.5103/78.7141이어서 **2,500회가 선택됐다. 학습을 오래 하는 방법은 채택하지 않았다.**

이후 B에서 배경 일부를 큰 값을 내는 I 영역으로 오인한 문제가 드러났다. 단순한 보완으로 임계값 보정 표본과 안전 여유를 늘렸다. `(영역당 보정 표본 수, 안전 여유)` 후보 `(1024, .5)`, `(16384, 1.5)`, `(65536, 2.5)`를 공개 설정의 seed 1729·8071, 영역당 8192개 표본에서 비교했다. 평균은 각각 70.5762/78.2887/77.1820이었고 **16384 / 1.5를 최종 기본값으로 선택했다.**

| 설정 | public | A | B |
|---|---:|---:|---:|
| 기존 보정 1024 / .5 | 83.92 / 16.753초 | 89.51 / 11.693초 | 68.15 / 16.408초 |
| 최종 보정 16384 / 1.5 | 77.58 / 26.272초 | 85.50 / 20.764초 | 72.74 / 24.920초 |
| 참고: 공식 baseline | 37.09 / 11.341초 | 31.22 / 11.292초 | 32.76 / 11.392초 |

같은 세 번째 workflow에서 측정한 점수와 전체 학습 subprocess 시간이다. 채점 subprocess는 별도로 약 1.5~1.7초였다. **모든 분할에서 점수가 오른 변경은 아니다.** A는 4.01점 하락하고 B는 4.59점 상승했다. 큰 생성 검증 표본의 평균과 판정 안정성을 기준으로 선택했으며, 기존 성능을 재현하려면 `--validation-per-region 1024 --i-safety .5`를 사용한다.

이 보완은 A/B의 첫 평가를 본 뒤 개발했다. 최종 A/B 수치는 개발 후 재평가이며 새 비공개 데이터에서의 독립 확증으로 소개하지 않는다. 실측에서는 선택값을 CLI에 명시했고, 이후 같은 값을 코드의 기본값으로 옮겼다. 그 기본값 변경 외에 측정 후 학습 로직을 바꾸지 않았다. 모델 크기 **17,424개 파라미터**, 등록 buffer 없음, dropout 출력 범위는 그대로다.

## 결과를 읽는 기준

- **실행 시간**은 새 Python 프로세스의 import, 모델·데이터 로딩, 학습·추론, 결과 저장을 포함한다. 다운로드·설치·별도 채점 시간은 제외한다. Potato는 대화형 심판의 피드백 처리도 포함한다.
- 표의 각 항목은 한 번의 측정값이다. Potato 기본값 A와 Ghost 원본 B는 확인을 위해 한 번씩 더 실행했고 별도 기록했다. OS 파일 캐시와 GPU 드라이버 캐시는 이미 준비돼 있을 수 있다. 작은 시간 차이를 확정적인 속도 개선으로 해석하지 않는다.
- GPU 평가는 문제별로 순서를 나눠 단독 실행했다. 가벼운 CPU 작업과 파일 다운로드는 병행했다. 원래 대회 장비·컨테이너와 동일한 환경은 아니다.
- A/B 정답은 별도 scorer에서만 읽는다. Potato의 비공개 임베딩도 심판에만 전달한다. 예외적으로 Dilemma의 이미지 라벨은 문제에서 허용한 공격 목표다. Field의 설정 JSON은 문제에서 제공하는 학습 입력이다.
- 설정은 학습 데이터 holdout이나 공개 개발 데이터로 고른 후 A/B에서 평가했다. Dilemma의 시간 예약과 Field의 추가 보완은 첫 A/B 결과를 본 뒤 개발했으므로 재평가로 구분했다. 공개 개발 점수만 좋아지고 A/B에서 효과가 없는 변경도 그대로 남겼다.

## 실행 환경

일반 다섯 문제는 Windows, Python 3.11.0, Intel Core Ultra 9 185H, RAM 약 32 GiB에서 실행했다. 모델 추론은 NVIDIA GeForce RTX 4070 Laptop GPU 8 GB를 사용했다. Robot과 Potato는 CPU 4 threads를 사용했다. PyTorch 2.5.1+cu121, torchvision 0.20.1+cu121, transformers 4.45.0, NumPy 2.3.3, SciPy 1.16.2, scikit-learn 1.7.2, timm 1.0.22를 사용했다.

Field는 공식 보호 런타임을 실행할 수 있는 GitHub Actions 표준 Linux CPU runner에서 별도로 측정했다. Ubuntu 24.04, CPython 3.13, PyTorch 2.8.0 CPU, CPU 4 threads를 사용했다. 따라서 다른 다섯 문제와 Field의 초 단위 수치를 같은 장비의 결과로 비교하면 안 된다.
