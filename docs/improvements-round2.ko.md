# 단순한 방법으로 개선한 2차 A/B 비교

측정일: 2026-10-16. 기준은 1차 실험을 마친 commit [`991a49b`](https://github.com/Sy5h/IOAI/tree/991a49b48092286967b5bd7cada465e336ebc4af)이다. 큰 모델을 추가하지 않고 탐색 폭, 입력 특징, 후보 확률, 표본 경계를 바꿨다. [1차 실험 기록](benchmark.ko.md)은 그대로 보존했다.

## 점수와 실행 시간

점수는 각 문제의 공식 채점식을 100점 척도로 나타낸 값이다. 문제 간 점수의 의미는 다르다. 화살표는 **1차 기본 코드 → 2차 채택 코드**다.

| 문제 | A 점수 | B 점수 | A 시간(초) | B 시간(초) |
|---|---:|---:|---:|---:|
| Find the Order | 76.52 → **77.77** | 74.09 → **77.92** | 362.1 → 277.7 | 267.0 → 254.3 |
| Robot Chasing | 64.92 → **66.31** | 63.94 → **64.47** | 111.938 → 73.192 | 66.031 → 55.707 |
| Potato | 44.25 → **47.42** | 48.90 → **54.40** | 7.063 → 3.656 | 6.391 → 4.844 |
| IOAI Field | 85.50 → **91.52** | 72.74 → **81.86** | 19.862 → 21.264 | 18.508 → 25.067 |

Double Agent Dilemma와 Ghost of the Machine은 이번에 코드를 바꾸거나 다시 측정하지 않았다. 이전 결과는 각각 A/B **97.54/97.38**, **90.52/90.81**이며 실행 시간도 [1차 기록](benchmark.ko.md)의 값이다.

시간 비교에는 다음 차이가 있다.

- **Order의 기준 시간은 1차 측정값**이고, 개선안만 이번에 새 프로세스로 실행했다. 동일 시점의 쌍별 속도 실험이 아니므로 A의 시간 감소를 beam 변경의 효과로 해석하지 않는다. 캐시·시스템 부하 등도 영향을 준다.
- **Robot·Potato·Field는 기준 코드와 개선 코드를 이번에 각각 새 프로세스로 실행했다.** Robot과 Order의 일부 실행은 동시에 진행했으므로 Windows CPU 부하가 벽시계 시간에 영향을 줄 수 있다.
- 로컬은 Windows, Intel Core Ultra 9 185H, CPU 4 threads, RTX 4070 Laptop 8GB다. Order만 이번 변경 문제 중 GPU를 사용한다. Field는 GitHub Actions의 별도 Linux CPU 4 threads에서 실행했다. 다른 문제나 다른 컴퓨터의 시간끼리 직접 비교하지 않는다.
- 시간은 풀이 프로세스 시작부터 종료까지다. import·모델 로딩·학습·풀이 결과 저장을 포함하고 다운로드와 별도 채점을 제외한다. Field의 풀이 산출물은 학습된 모델이므로 표의 시간은 학습·저장 시간이며, 공식 채점 중 추론 시간은 결과 JSON에 따로 있다.
- 분할별 한 번의 실행이다. 반복 평균이나 통계적 유의성, 원래 대회 환경의 시간을 주장하지 않는다.

## 무엇을 간단하게 바꿨나

### Order: 너무 일찍 버리던 후보를 더 남기기

Whisper와 Qwen, 화자 특징은 그대로다. `--beam` 기본값 한 줄을 **16에서 256**으로 바꿨다. 연결 점수가 당장 조금 낮아도 전체 순서가 좋아질 수 있는 후보를 더 남긴다.

공식 public/pretrain 20개 대화에서 미리 정한 8개 설정을 비교했다. 캐시된 연결 점수를 사용한 개발 평균은 75.8797 → 80.0778이었다. 이는 전체 풀이 시간이나 최종 A/B 점수가 아니다. 캐시 생성은 LM batch 8이고 최종 실행은 기존 batch 4이므로 개발 점수와 최종 실행 점수도 동일한 조건은 아니다. 공개 pretest 새 실행은 75.9140 → 79.1531이었다. A/B 최종 실행에서는 캐시된 전사·연결 점수를 재사용하지 않았다.

### Robot: 주변 칸의 의미를 바로 보여주기

작은 로봇별 MLP와 전체 격자를 유지하고, **로봇 주변 5×5칸의 목표·토큰 색·장애물 표시와 집기·놓기 조건**을 입력에 붙였다. 원래 1,328개 특징에 주변 격자 250개와 상호작용 44개를 추가해 1,622개를 사용한다. 모델이 스스로 찾아야 했던 가까운 칸의 의미를 입력에서 바로 보여주는 변경이다.

학습 자료의 고정 48,000/12,000 분할에서 기준 MLP는 64.7333점, 선택안은 66.0833점이었다. 경로 정보를 붙인 HGB는 66.5083점이지만 이전 HGB와 동점이고 165.0초가 걸려 채택하지 않았다. 간단한 MLP 선택안은 88.5초였다. 경로 요약 MLP 60.9750점, 상대 격자로 대체한 MLP 58.8167점, 절대 목표 마스크 추가 64.1417점도 기록하고 제외했다. 이 차이는 이번 표현·모델 조합의 실측이며 특정 특징의 일반적인 우열을 증명하지 않는다.

### Potato: 한 가지 확신에 몰리지 않고 더 일찍 맞혀보기

온도 0.03·0.06·0.12로 계산한 후보 확률을 각각 정규화한 뒤 평균낸다. 비교 응답의 오차 하한은 0.12로 두고, **8턴부터는 가장 가능성 높은 단어를 직접 제안**한다. 별도 모델이나 임베딩을 추가하지 않았다. 정보량 계산을 덜 하므로 이번 실행에서는 점수와 시간 모두 개선됐다.

공개 임베딩만으로 만든 세 가지 잡음 심판에서 12개 단순 후보를 비교했다. 첫 64단어의 평균은 28.875 → 35.979였지만, 겹치지 않는 128단어·다른 잡음 seed의 확인에서는 25.026 → 25.563으로 개선 폭이 작았다. 강한 왜곡에서 나빠진 경우도 있어 일반화가 확실하다고 주장하지 않는다. 이 합성 점수들은 공식 점수가 아니다. 최종 공식 공개 A/B 120게임씩에서는 해결 게임 수가 **63→68개, 69→75개**로 늘었다.

### Field: 첫 I의 안쪽을 표본으로 직접 잡기

첫 I는 잘못 예측하면 큰 오차가 생겨 기존 MLP가 보수적으로 버리는 점이 많았다. 공개 생성기로 얻은 I 표본을 가장 길게 퍼진 축(PCA)을 따라 **32개 띠**로 나누고, 각 띠의 표본 안쪽에 볼록 다각형을 만든다. 비-I 보정 표본이 들어가는 조각은 버린다. 추론에서는 이 조각 안에서만 첫 I 출력을 허용한다. 나머지 작은 MLP와 선형식은 유지한다.

기존 코드와 `affine/PCA × 16/32띠`를 public의 새 생성 검증 표본에서 비교해 PCA 32띠를 고정했다. 보호된 생성기 내부나 정답 경계를 읽거나 복제하지 않았다. 공식 `make_batch`와 평가 함수를 그대로 사용했다. 경계 계수까지 모델 파라미터로 집계하며 최대 19,344개로 공식 제한 20,260개 미만이다. 등록 buffer도 없다.

## 검증 범위

후보는 공개 개발 자료 또는 학습 데이터 holdout에서 선택하고 이번 A/B 실행 전에 고정했다. 다만 A/B 자체는 1차 실험에서 이미 관찰한 공개 자료다. 따라서 이번 결과는 **공개 자료를 이용한 개발 재평가**이며, 새 비공개 데이터에서의 독립 검증이나 실제 대회 서버 제출 결과가 아니다. A/B 결과에 맞춘 추가 파라미터 탐색은 하지 않았다.

평가용 정답과 Potato 심판용 임베딩은 채점기가 사용하며 풀이에 넘기지 않는다. 이 연구용 프로세스 분리를 OS 보안 격리로 표현하지 않는다. 공개 저장소에는 데이터·모델 가중치·정답 파일·원문 전사 캐시를 올리지 않았다. 코드, 익명화한 실행 로그, 소스 해시, 명령과 결과를 함께 보존한다.

최종 소스와 노트북 검사는 [검증 기록](validation.ko.md)을 확인한다. 소규모 단위 테스트 통과와 실제 공식 문제 점수는 별개의 증거다.
