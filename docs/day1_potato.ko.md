# Day 1 — Potato

이 구현은 **심판 응답으로 후보 확률을 갱신하고, 초반에는 정보를 얻는 질문을, 후반에는 유력한 정답을 고르는 방법**이다. 추가 모델 학습 없이 제공된 공개 임베딩만 사용한다. 현재 공개된 공식 A/B 데이터와 원래 심판의 비교·점수 규칙으로 로컬 재평가했다. 대회 서버에 제출한 결과는 아니다.

## 문제와 제공 코드의 차이

정답은 1,602개 단어 중 하나이며 30턴 안에 직접 제안해야 한다. 시작 비교는 `lamp`와 `potato`, 이후에는 직전 승자와 새 단어를 비교한다. 정답을 찾으면 10턴까지 1점, 20턴 0.8점, 30턴 0.6점이며 실패는 0점이다. 전체 120게임, 모델 준비, 추론을 합쳐 10분이다. 노트북 크기 제한은 1MB다.

공식 baseline은 현재 승자와 가까운 단어부터 제안한다. 여기서는 모든 비교 이력을 사용한다. 공개 임베딩과 실제 심판 임베딩이 다르므로 비교 하나가 어긋났다고 후보를 완전히 삭제하지 않는다. 공식 baseline 또는 위원회 점수를 이 구현의 점수로 인용하지 않는다.

## 실제 알고리즘

1. 임베딩을 정규화하고 `S = E @ E.T`를 한 번 계산한다. 1,602×1,602 float32 행렬은 약 10MB다. 새 게임에서는 이 행렬을 재계산하지 않는다.
2. 승자 `w`, 패자 `l`을 받으면 후보 `h`별 `S[h,w]-S[h,l]`를 계산한다. 양수이면 관측과 일치하며, 차이가 작으면 증거도 약하게 취급한다.
3. `error_floor + (1-2*error_floor)*sigmoid(margin/temperature)`를 관측 가능도로 사용한다. 온도 .03/.06/.12의 로그 가능도를 각각 누적하고, 각 분포를 정규화한 뒤 같은 비중으로 평균한다. 하나의 과신한 분포가 신중한 분포까지 지우지 않도록 한다. 추가 모델을 학습하는 과정은 없다.
4. 초반에는 상위 후보와 일부 탐색 단어를 질문으로 검토한다. 질문의 예상 정보량과 그 단어가 정답일 확률을 함께 평가한다. 모든 후보에서 응답이 불확실한 질문은 정보량이 낮다.
5. 확률이 충분히 모였거나 8턴부터는 가장 유력한 미제안 단어를 제안한다. 새 피드백으로 확률은 계속 갱신한다. 이미 실패한 제안만 확실히 제외한다.

기본값은 중심 `temperature=0.06`, `error_floor=0.12`, `posterior_mode=mixture`, `guess_after=8`, 탐색 후보 수 256이다. 중심 온도의 절반·동일·두 배를 섞는다. 최적값이나 최고점 방법이라고 주장하지 않는다. `same` 응답은 유사도 차이가 작은 후보에 유리하게 반영하며, 같은 단어끼리의 비교는 정보가 없는 것으로 처리한다.

## 바로 실행

필요 라이브러리는 NumPy다. 입력 폴더에는 공식 `vocabulary.json`, `public_embeddings.npy`가 있어야 한다.

```bash
python solutions/day1_potato.py --data-dir dataset
```

이 명령은 JSON 프로토콜을 표준입력으로 받으므로 터미널에서 실행하면 심판 입력을 기다린다. 임의로 텍스트를 입력하는 명령이 아니다. 표준출력은 `{"new_word": "..."}`만 내보내며 준비 로그는 표준오류로 보낸다.

공식 제출에서는 이 Python 파일 전체를 `solution.ipynb`의 코드 셀에 넣는다. 심판은 노트북을 Python으로 변환해 한 번 실행한다. 원래 baseline의 프로토콜 셀을 중복으로 추가하면 안 된다. 이 파일에 데이터 로드, `PublicEmbeddingPlayer`, 게임마다 새 인스턴스를 만드는 루프가 모두 들어 있다. 노트북에서 셀을 실행할 때는 stdin 루프에 들어가지 않는다. 실제 제출 전에는 변환된 Python을 공식 `local_test.py`로 검사한다.

```bash
python local_test.py solution.ipynb --limit 5
```

로컬 심판은 공개 임베딩을 사용하므로 높은 로컬 점수가 실제 비공개 임베딩에서도 유지된다고 보장하지 않는다. 기본 `--budget-seconds 580`은 막바지에 비싼 질문 평가를 생략하는 기준이며 전체 실행을 강제로 제한하는 타이머는 아니다.

## 실수하기 쉬운 부분

- 처음 보인 `lamp`, `potato`는 이미 추측한 단어가 아니다. 정답이 둘 중 하나이면 직접 제안해야 이긴다.
- 한 게임의 상태는 초기화하지만 유사도 행렬은 전체 게임에서 공유한다.
- 실패한 단어를 반복 제안하지 않는다. 단순히 비교에 등장했다는 이유만으로 제외하지 않는다.
- 공개 임베딩만으로 후보를 완전히 잘라내는 이진탐색은 실제 정답을 잃을 수 있다.
- 정답을 심판 파일에서 읽거나 평가 정답을 하드코딩하는 경로는 없다.

## 1차 실측: 단일 온도 기준선

2026-10-16, Windows / Intel Core Ultra 9 185H / NumPy 2.3.3 / BLAS 4스레드에서 새 프로세스로 실행했다. GPU는 사용하지 않았다. 시간은 import, 임베딩 로딩, 120게임 전체와 종료를 포함하며 다운로드·채점 준비는 제외한다. 각 표 항목 1회 측정이며 별도의 harness 이식 확인에서도 A 점수가 같았다.

| 방법 | 공개 임베딩·public 120 | 실제 심판 임베딩·공개된 A 120 | 실제 심판 임베딩·공개된 B 120 |
|---|---:|---:|---:|
| 공식 원본 nearest baseline | 36.00 / 1.281초 | 15.00 / 1.578초 | 17.08 / 1.469초 |
| 당시 기본값 .06, 단일 분포 | 84.90 / 6.281초 | 44.25 / 6.406초 | 48.90 / 8.047초 |
| 개발셋에서 고른 .008 후보 | 97.80 / 4.047초 | 44.17 / 9.391초 | 49.17 / 8.438초 |

`.008`은 public target 120개를 제외한 개발 단어 160개에서 `.06/.03/.015/.008` 중 선택했다. 이 개발 평가는 공개 임베딩을 심판으로 쓴다. 개발 점수는 66.55 → 93.81이었지만 실제 심판 임베딩 A/B에서는 개선이 유지되지 않았다. **97.80을 실제 대회 성능으로 해석하면 안 된다. 1차 실험에서는 .06을 유지했다.** 당시 .008 실험은 현재 코드에서 `--temperature .008 --posterior-mode single --error-floor .08 --guess-after 24`로 재현할 수 있다. 해당 1차 실험에서는 A/B를 재튜닝에 사용하지 않았다.

데이터는 공식 Hugging Face revision `122716fc56a212e58b1756158bdeb4c2ea2da5e6`이다. solver는 공개 임베딩과 비교 피드백만 받으며 A/B 정답과 private 임베딩은 별도 scorer 프로세스만 읽는다. 동일 머신의 프로세스 분리이며 대회 컨테이너 격리를 재현한 것은 아니다. 원본 로그·정확한 실행 인자·다운로드 해시를 보관했고, 공유용 기록은 `benchmarks/results_potato_ghost.json`에 정리한다.

저장소 루트에서 재현할 때 공식 데이터는 Git에서 제외한 `work/` 폴더에 둔다.

```bash
python benchmarks/download_potato_ghost.py --data-root work/bench-potato-ghost --only potato
python benchmarks/benchmark_potato.py --data-dir work/bench-potato-ghost/potato-source/public --evaluation-dir work/bench-potato-ghost/evaluation-assets/potato/private --suite leaderboard_a --output-dir work/bench-potato-ghost/results --tag reproduce-a
```

합성 테스트는 비교 방향, 약한/강한 증거, 동률, 초기 단어 후보 유지, 실패한 제안 제외, 게임 초기화, 프로토콜 출력 및 작은 가상 게임 완주를 확인한다. 비공개 임베딩에서의 실전 성능 테스트를 대신하지 않는다.

## 2차 실측: 온도 혼합과 빠른 직접 제안

이전 A/B 점수는 이미 알려져 있었다. 이번에는 공개 임베딩만으로 만든 합성 잡음 심판에서 설정을 고른 뒤 고정하고 A/B를 다시 평가했다. **기존 A/B의 영향을 전혀 받지 않은 독립 확증은 아니며, 개발 후 재평가다.** 실제 심판 임베딩이나 A/B 정답을 후보 선택·학습·풀이 입력으로 사용하지 않았다.

공개 target을 제외한 64단어에서 미리 정한 12개 설정을 비교했다. 공개 임베딩을 무작위 128차원 또는 32차원으로 투영하거나, 128차원 투영에 단어별 잡음을 더한 세 합성 심판의 평균을 선택 기준으로 삼았다. 원래 공개 임베딩과 똑같은 심판 점수는 선택에 넣지 않았다. 비교 투표, 최근 증거 강조, 더 큰 오류 하한, 직접 제안 시점, 온도 혼합을 검사했다.

선택된 방법은 **온도 .03/.06/.12의 확률 평균 + 오류 하한 .12 + 8턴부터 직접 제안**이다. 세 잡음 심판 평균은 기존 28.875→35.979였고, 겹치지 않는 128단어·새 투영 seed의 확인에서는 25.026→25.563이었다. 후자의 이득은 작고 32차원 강한 왜곡에서는 8.969→7.109로 나빠졌다. 이 수치는 공식 점수가 아니며 모든 표현 차이에 대한 개선을 뜻하지 않는다. 단순 투표는 원래 공개 공간에서 90.844였지만 잡음 평균 23.719로 낮아서 선택하지 않았다.

선택을 고정한 뒤 각 분할에서 기준 commit `991a49b48092286967b5bd7cada465e336ebc4af`와 새 코드를 한 번씩 새 프로세스로 실행했다.

| 이번 2차 평가 | 기존 단일 분포 / 시간 | 최종 혼합 분포 / 시간 | 성공 게임 수 |
|---|---:|---:|---:|
| 공개된 A, 120게임 | 44.2500 / 7.063초 | **47.4167 / 3.656초** | 63→68 |
| 공개된 B, 120게임 | 48.9000 / 6.391초 | **54.4000 / 4.844초** | 69→75 |

A +3.1667점, B +5.5000점으로 양쪽이 올라 기본값을 교체했다. 이후 A/B로 설정을 더 바꾸지 않았다. 실행 시간에는 import·공개 임베딩 로딩·120게임·종료를 포함한다. 심판 준비와 기존 다운로드는 제외한다. CPU 4 threads이며 다른 작업의 CPU·GPU·파일 작업이 병행될 수 있고 OS 캐시가 준비돼 있을 수 있다. 1회씩의 시간 측정이므로 정밀한 속도 개선 비율로 해석하지 않는다. GPU와 추가 모델은 사용하지 않았다.
