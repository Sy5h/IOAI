# 사전 과제와 본선 문제의 연결 관계

아래 연결은 공개된 과제들의 입력·목표·풀이 방법을 비교한 학습용 분석입니다. 공식 문서가 개별 문제의 일대일 대응표를 선언한 것으로 해석하면 안 됩니다. 특히 Day 2의 연결은 공통 기술에 대한 간접 연결입니다.

| 사전 과제 | 가장 가까운 본선 문제 | 이어지는 기술 | 본선에서 달라지는 핵심 |
|---|---|---|---|
| [Operation Night Watch](https://github.com/IOAI-official/IOAI-2026/blob/main/At-Home-Round/Home-Task-1.ipynb) | [Find the Order](day1_find_the_order.ko.md) | 오디오 전처리, 사전학습 음성 모델 활용, 작은 GPU 예산 | 소리 종류 분류에서 대화 조각 순서 복구로 변경. ASR·화자 구분·순서 탐색이 필요 |
| [Robot Delivery Academy](https://github.com/IOAI-official/IOAI-2026/blob/main/At-Home-Round/Home-Task-2.ipynb) | [Robot Chasing](day1_robot_chasing.ko.md) | 관측→행동 지도학습, 위치 특징, 집기·놓기 상태 구분 | 전체 배송 에피소드 성공에서 독립 스냅샷 행동 정확도로 변경. 여섯 로봇의 서로 다른 행동 습관과 자연어 임무 추가 |
| [The Analytical Language of John Wilkins](https://github.com/IOAI-official/IOAI-2026/blob/main/At-Home-Round/Home-Task-3.ipynb) | [Potato](day1_potato.ko.md) | 제한된 질문 수, 후보 확률, 정보량, 사전 계산, 오라클 오차 대응 | 동물에 대한 yes/no 질문에서 현재 승자와 새 단어의 의미 유사도 비교로 변경 |

## Night Watch → Find the Order

Night Watch는 기존 소리 분류기의 능력을 유지하면서 새로운 소리를 학습하는 오디오 과제입니다. Find the Order에서는 음성 조각에서 텍스트와 화자 정보를 뽑아야 합니다. 옮겨 쓸 수 있는 부분은 파형 읽기, 샘플레이트 정리, 배치 추론, 허용된 음성 모델을 이용하는 코드입니다.

분류 헤드나 기존/신규 클래스 학습 목표는 그대로 재사용하지 않습니다. Find the Order에서 새로 필요한 것은 prefix 고정, 대화 연결 점수, 순열 생성과 역순열 출력입니다. 따라서 이 연결은 오디오 처리 기반에 대한 연결이며, 동일한 학습 문제라는 뜻은 아닙니다.

## Robot Delivery Academy → Robot Chasing

두 과제 모두 관측에서 다음 행동을 예측하는 지도학습이 출발점입니다. 좌표·목표와의 거리·운반 상태를 특징으로 만드는 방식은 그대로 도움이 됩니다.

하지만 인터페이스와 목표가 다릅니다.

| 항목 | 사전 과제 | 본선 |
|---|---|---|
| 평가 단위 | 배송 에피소드 전체의 성공 | 독립 스냅샷마다 다음 행동 |
| 이동 ID | 0=아래, 1=위, 2=오른쪽, 3=왼쪽 | 0=위, 1=아래, 2=왼쪽, 3=오른쪽 |
| 집기/놓기 | 현재 위치의 depot | 바라보는 방향의 인접 칸 |
| 정책 | 배송 시연 행동 학습 | 로봇별로 다른 일관된 행동 학습 |
| 명령 | 목적지·소포 상태 | 색·물체·동사가 포함된 영어 임무 |

사전 과제의 action mask를 본선에 그대로 붙이면 오류가 생길 수 있습니다. 본선에서 막힌 방향으로 이동하는 명령도 몸을 돌리는 의미가 있습니다. 사전 과제에서 높은 단일 행동 정확도가 완주 성공을 보장하지 않는다는 교훈도 중요하지만, 본선에서는 이전 상태를 기억하는 코드를 추가하면 안 됩니다. 행들이 독립이기 때문입니다.

## John Wilkins → Potato

두 과제에서 가장 잘 옮겨지는 것은 후보를 관리하는 코드입니다. 질문과 후보의 관계를 미리 계산하고, 매번 남은 후보를 잘 나누는 질문을 고릅니다. 틀린 추측은 제거하고, 정보가 충분해지면 직접 답을 제안합니다.

John Wilkins는 동물별 yes/no 예상 응답표를 만들 수 있습니다. Potato는 `S = E @ E.T` 유사도 표로 비교 결과를 예측합니다. Potato의 심판은 제공 임베딩과 다른 표현을 쓰므로 예측과 관측의 불일치가 있을 때 정답 후보를 영구 삭제하지 않는 처리가 특히 중요합니다.

질문 후보의 제한도 다릅니다. Potato에서는 임의의 두 단어를 자유롭게 비교하지 못하고, 직전 승자와 다음 제안 단어가 비교됩니다. 따라서 사전 과제의 질문 선택 함수를 그대로 쓰지 말고 현재 승자를 조건에 포함해야 합니다.

## Day 2에 이어지는 공통 기술

| 본선 문제 | 도움이 되는 준비 경험 | 추가로 필요한 것 |
|---|---|---|
| Double Agent Dilemma | 사전학습 모델 로딩, freeze/fine-tune 구분, PyTorch autograd | 모델 가중치 대신 입력 픽셀의 gradient, 두 모델의 서로 다른 결정 경계, norm 벌점 |
| Ghost of the Machine | 텍스트 임베딩, 작은 지도학습 분류기, 그룹 단위 검증 | 사람→AI 단일 전환점, 문자 offset, 지수형 거리 점수 |
| IOAI Field | 작은 신경망 학습, 배치 처리, 정규화와 시간 예산 | 좌표 기반 회귀, 영역별 출력 범위, hard routing, dropout 변동성 평가 |

이 표는 학습 기술의 간접 연결입니다. Night Watch의 AST를 Ghost에 쓰거나, 사전 과제에서 사용한 모델을 본선에 그대로 가져올 수 있다는 의미가 아닙니다. 본선의 허용 모델 목록은 문제마다 별도로 적용됩니다.
